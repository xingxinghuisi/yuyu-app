# 语屿 Kotoba —— 宝塔面板部署说明

本文面向「会用宝塔面板、但不一定熟悉 Docker」的用户，覆盖从代码上传到上线访问的完整流程。
预计用时：20–40 分钟。

**部署形态**：单个 Docker Compose 项目（后端 FastAPI + 纯静态前端同源托管），SQLite 落盘在宿主机的 `./data` 目录持久化。

---

## 1. 准备工作

- **宝塔面板**：建议 9.x 以上版本。登录面板 → 「首页」确认版本号；过旧版本可先在「首页」右上角升级面板。
- **Docker 已安装**：面板左侧菜单 → 「Docker」。如果能看到 Docker 管理器界面并显示版本号（Docker ≥ 24 且 Compose v2 可用），即 OK；如果没装，宝塔会引导你一键安装 Docker。
- **VPS 要求**：1 核 2G 及以上（python:3.12-slim 构建过程比较吃内存，建议 2G 以上内存）。磁盘至少留 2GB 空间（镜像约几百 MB，SQLite 种子库很小）。
- **域名（如果要 HTTPS）**：域名已在 DNS 解析到这台 VPS 的公网 IP，例如 `kotoba.example.com`。可在 VPS 上 `ping kotoba.example.com` 确认返回本机公网 IP。不做域名也可以用 `http://VPS_IP:8000` 调试（不推荐长期裸 IP 使用）。

---

## 2. 上传代码

把本机 `~/workspace/yuyu-app` 整个目录传到 VPS，目标目录为 `/www/wwwroot/yuyu-app`（宝塔惯例目录，也方便管理）。

### 方式一：scp（命令行）

在本机（Mac / Linux）执行：

```bash
scp -r ~/workspace/yuyu-app root@<你的VPS_IP>:/www/wwwroot/yuyu-app
```

`-r` 表示递归复制整个目录。首次连接会提示确认主机指纹，输入 `yes` 并输入 VPS root 密码。

### 方式二：rsync（增量同步，适合以后更新）

```bash
rsync -avz --delete ~/workspace/yuyu-app/ root@<你的VPS_IP>:/www/wwwroot/yuyu-app/
```

> 注意最后的 `/`：`yuyu-app/` 表示同步目录**内容**；`--delete` 会删除目标端多余文件，更新代码时很顺手。

### 方式三：宝塔文件管理器（纯图形化）

1. 本机先把 `yuyu-app` 打包成 zip：`cd ~/workspace && zip -r yuyu-app.zip yuyu-app`。
2. 登录宝塔面板 → 左侧「文件」→ 进入 `/www/wwwroot/` 目录 → 「上传」→ 选择 `yuyu-app.zip`。
3. 上传完成后选中压缩包 → 右键「解压」→ 解压到当前目录，会生成 `/www/wwwroot/yuyu-app`。

三种方式任选其一。完成后确认 VPS 上的目录结构里有：`Dockerfile`、`docker-compose.yml`、`backend/`、`frontend/`。

## 3. 宝塔创建 Compose 项目

### 3.1 生成 JWT_SECRET

JWT_SECRET 是用户登录 Token 的签名密钥，**必须换掉默认值**。SSH 连上 VPS（或用宝塔左侧「终端」），执行：

```bash
openssl rand -hex 32
```

会输出一串 64 位十六进制字符，例如 `a3f9c1…`（不要用这个示例，请用你自己机器生成的）。复制备用。

### 3.2 在宝塔里新建 Compose 项目

1. 宝塔面板左侧菜单 → 「Docker」→ 顶部菜单栏切换到「Compose」页签 → 点击「添加项目」。
2. 填写表单：
   - **项目名称**：`yuyu-app`
   - **模板**：选择「Compose 模板」（默认选项，通常自动选中）
   - **项目目录 / 路径**：填 `/www/wwwroot/yuyu-app`（选上一步上传代码的目录）
   - **Compose 文件**：把下面内容粘贴进去（直接替换模板里的内容）：

```yaml
services:
  yuyu:
    build: .
    image: yuyu-app:latest
    ports:
      - "8000:8000"
    volumes:
      - ./data:/data
    environment:
      - JWT_SECRET=${JWT_SECRET:-dev-secret-change-me}
    restart: unless-stopped
```

3. **设置环境变量 JWT_SECRET**：在 Compose 项目的环境变量设置里（宝塔 Compose 项目的「环境变量」/ `.env` 编辑入口），添加一行：

```
JWT_SECRET=<你刚才 openssl 生成的密钥>
```

   > Compose 文件里的 `${JWT_SECRET:-dev-secret-change-me}` 表示：优先读取环境变量 JWT_SECRET，没设置时回退到默认值。**默认值 `dev-secret-change-me` 必须替换掉**，否则任何人都能伪造登录 Token。

4. 点击「确定」/「提交」启动。第一次启动会执行 `docker build`（下载 python:3.12-slim 基础镜像并安装依赖），需要几分钟。可以在「容器」页签里看到 `yuyu-app-yuyu-1` 容器从 `building` → `running`。

**备选（命令行方式）**：如果面板操作不顺，直接在 VPS 上：

```bash
cd /www/wwwroot/yuyu-app
export JWT_SECRET="$(openssl rand -hex 32)"
echo "JWT_SECRET=$JWT_SECRET" > .env   # 保存到 .env，避免重启丢失
docker compose up -d --build
```

## 4. 放行端口

分两层防火墙，**都要**检查：

1. **宝塔「安全」防火墙**：面板左侧 → 「安全」→ 「放行端口」→ 添加：
   - `8000`（仅调试用，验证阶段直连 `http://VPS_IP:8000` 需要）
   - `80`、`443`（生产环境走域名 + HTTPS 时必须）
   
   > 生产环境上线后，建议把 `8000` 的放行规则删掉，只通过下面的 Nginx 反向代理访问，避免后端直接暴露公网。

2. **云厂商安全组**（阿里云 / 腾讯云 / 华为云等）：进入云控制台 → ECS 实例 → 安全组 → 入方向规则，放行 `80/tcp`、`443/tcp`（以及调试期的 `8000/tcp`）。
   
   > 如果浏览器访问超时但容器正常，十有八九是安全组没放行，先查这里。

## 5. Nginx 反向代理 + HTTPS

### 5.1 添加站点

1. 宝塔左侧 → 「网站」→ 「添加站点」。
2. 域名填写你的域名（如 `kotoba.example.com`），根目录随便填（会被反向代理接管，用默认即可），PHP 版本选「纯静态」。
3. 提交后在站点列表点击该域名 → 「反向代理」→ 「添加反向代理」：
   - 目标 URL：`http://127.0.0.1:8000`
   - 名称：`yuyu`
   - 提交。前端是纯静态页面由后端同源托管，**不需要配置 websocket**。

生成的 `location /` 代理配置大致如下（宝塔会自动生成，可对照检查）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

> 如果以后反代后登录态异常（如频繁掉登录），优先检查 `Host` 和 `X-Forwarded-Proto` 这两行是否存在。

### 5.2 申请 SSL 证书

1. 站点设置 → 「SSL」页签 → 选择「Let's Encrypt」→ 勾选你的域名 → 「申请」。
2. 申请成功后，打开右上角「强制 HTTPS」开关。以后访问 `http://` 会自动跳转到 `https://`。
3. Let's Encrypt 证书 90 天有效，宝塔默认会自动续签；可以在「计划任务」里确认有一条 SSL 续签任务。

## 6. 验证

```bash
# 1) 容器本机健康检查（SSH 到 VPS 上执行）
curl -s http://127.0.0.1:8000/api/health
# 期望返回类似 {"status":"ok"} 的 JSON

# 2) 确认容器在运行
docker ps --filter "name=yuyu"
```

然后浏览器打开 `https://你的域名`（或调试期 `http://VPS_IP:8000`），应该看到语屿的**登录页**。尝试注册一个账号并登录，能进入背词主界面即部署成功。

> 首次启动时容器会自动从种子库初始化 SQLite（`/data/app.db`），初始化过程健康检查可能短暂失败，等 10–20 秒再试。

## 7. 后续更新流程

代码有更新后（比如修复 bug、加功能）：

```bash
cd /www/wwwroot/yuyu-app
# 1) 拉新代码（用 rsync 或重新上传覆盖，二选一）
rsync -avz --delete ~/workspace/yuyu-app/ root@<你的VPS_IP>:/www/wwwroot/yuyu-app/

# 2) 重新构建并启动（VPS 上执行）
docker compose up -d --build
```

- `./data` 是挂载的宿主机目录（volume），用户数据（`app.db`）**不受镜像重建影响**，放心 `--build`。
- `up -d` 是幂等的：没变化的服务不会重启。

### 回滚

更新前先给当前能用的镜像打个 tag 做快照：

```bash
cd /www/wwwroot/yuyu-app
docker tag yuyu-app:latest yuyu-app:backup-20261008   # 日期换成当天
docker compose up -d --build   # 然后正常更新
```

如果新版本出问题，回滚只需：

```bash
docker compose down
docker tag yuyu-app:backup-20261008 yuyu-app:latest
docker compose up -d   # 不加 --build，直接用旧镜像启动
```

数据在 `./data` 里，回滚镜像不会丢数据。

## 8. 备份

核心数据就是宿主机上的 `/www/wwwroot/yuyu-app/data/app.db` 这一个 SQLite 文件。

### 手动备份

```bash
cp /www/wwwroot/yuyu-app/data/app.db /www/backup/yuyu-app-db-$(date +%F).db
```

### 宝塔计划任务自动备份（推荐）

1. 宝塔左侧 → 「计划任务」→ 「添加任务」：
   - 任务类型：Shell 脚本
   - 任务名称：`备份语屿数据库`
   - 执行周期：每天一次（建议凌晨，如 3:00）
   - 脚本内容：

```bash
#!/bin/bash
BACKUP_DIR=/www/backup/yuyu
mkdir -p "$BACKUP_DIR"
# SQLite 在线热备（比直接 cp 更安全，避免拷到一半写入的数据）
sqlite3 /www/wwwroot/yuyu-app/data/app.db ".backup '$BACKUP_DIR/app-$(date +%F).db'"
# 只保留最近 14 天
find "$BACKUP_DIR" -name 'app-*.db' -mtime +14 -delete
```

2. 保存后点「执行」手动跑一次，确认 `/www/backup/yuyu/` 里生成了备份文件。

> 恢复时：先 `docker compose stop`，把备份文件拷回 `data/app.db`，再 `docker compose start`。

## 9. 常见问题

| 现象 | 排查 |
|---|---|
| **端口被占用**：容器起不来，日志报 `port is already allocated` | `ss -tlnp \| grep 8000` 看谁占了 8000；要么停掉占用者，要么改 compose 的端口映射为 `"8001:8000"`（反向代理目标也同步改成 8001）。 |
| **JWT_SECRET 未改**：能跑但登录 Token 可被伪造 | 检查 `.env` / Compose 项目环境变量里 `JWT_SECRET` 是否还是 `dev-secret-change-me`；改成 `openssl rand -hex 32` 生成的值后 `docker compose up -d` 重启。 |
| **SQLite 权限问题**：日志报 `unable to open database file` / `readonly` | volume 目录属主不对。`ls -ld /www/wwwroot/yuyu-app/data` 确认容器内运行用户可写；通常以 root 起容器不会有问题，若用了 `user:` 指令则需 `chown -R <uid> data/`。 |
| **前端 404**：API 正常但页面打不开 / 白屏 | 进容器确认前端文件拷进了镜像：`docker exec <容器名> ls /app/frontend` 应该能看到 `index.html` 等文件；看不到说明构建时 frontend 没拷进去，检查 Dockerfile 的 COPY 指令后重新 `--build`。 |
| **容器不断重启** | `docker logs yuyu-app-yuyu-1 --tail 100` 看最后的报错；常见原因是 requirements 安装失败（网络问题）或 `app.main` 导入报错。构建阶段失败则看 `docker compose up --build` 的前台输出。 |
| **浏览器访问超时但容器正常** | 先 `curl 127.0.0.1:8000/api/health` 确认本机通；不通查容器日志，通则查宝塔「安全」放行 + 云厂商安全组（第 4 节）。 |
| **反代后页面能开但登录掉线** | 检查 Nginx 反向代理配置里有没有 `proxy_set_header Host $host;` 和 `X-Forwarded-Proto`（第 5 节示例）。 |
